# 输出规则

输出规则用于维护回答详略、结构、模板、默认字数、结论先行和展开条件。默认仍用中文 Markdown，结论先行。

## 默认详略

- 默认诊断：300-600 字，包含结论、计划定位、关键证据、风险判断和优化动作。
- 定位类问题：只给命中计划、查询条件、日期口径和必要消歧，不做深度诊断。
- ROI<1 简单亏损问题：100-200 字，最多 2 条证据，给保守动作。
- 深度复盘、为什么、怎么优化、要不要暂停：展开完整模板。
- 批量巡检：先分“待放量、待降本、待暂停观察、数据缺口”，再列重点计划；不要粘贴完整 rows。

## 用户反馈映射

- “太啰嗦/少说点”：缩短为结论 + 关键证据 + 动作，少于 250 字，除非用户要求详细。
- “只要结论”：只输出建议动作、最大证据和最大风险。
- “要详细报告”：使用完整模板，可展开到 600 字以上，但仍避免粘贴完整工具 JSON。
- “以后都按这个格式”：生成输出规则变更单，标注适用范围是全局、项目级还是某类问题。
- “先说风险/先说动作”：调整对应场景的段落顺序，但保持指标和日期口径可追溯。

## 结构模板

默认模板：

```markdown
# 广告计划诊断

## 结论
先给建议：放量、稳投、降本、暂停观察或继续观察。再用一句话说明最大问题和证据强度。

## 计划定位
说明用户线索、命中计划、查询日期和关键口径；多候选时只列候选并要求确认。

## 关键证据
- 指标｜判断｜数据依据

## 风险判断
说明确定异常、数据延迟、数据不足或工具失败。

## 优化动作
- 策略类别｜执行方式｜原因｜观察指标
```

简短模板：

```markdown
结论：建议【动作】。
证据：【1-2 条核心指标】。
风险：【缺口或不确定性】。
下一步：【观察指标或保守动作】。
```

## 规则来源说明

引用项目、分析或输出规则时，必须在回答中用一句话说明来源：

- 采用本地规则：`规则来源：本地 output-rules.md，适用于该项目。`
- 采用仓库规则：`规则来源：Skill output-rules.md。`
- 采用通用规则：`规则来源：通用输出规则。`

## 本地覆盖

本地输出规则可放在 `~/.codex/ad-data-analyst/rules/output-rules.md` 或同名 YAML。用户偏好只应在明确要求“以后都按这个”或“同步为规则”时写入规则；普通一次性要求只在当前回答生效。
