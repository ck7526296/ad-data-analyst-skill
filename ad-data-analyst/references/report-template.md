# 输出模板

## 单计划诊断

```markdown
# 广告计划诊断

## 结论
建议：放量 / 稳投 / 降本 / 暂停观察 / 继续观察。
最大问题：用一句话说明核心原因。
证据强度：充分 / 有风险但需观察 / 数据不足。

## 计划定位
用户线索：...
命中计划：planName / planId / productCode / returnDataCode / 负责人 / 查询日期。
口径说明：单计划诊断 / 同项目对比 / 同回传编码对比 / 历史日期诊断。

## 关键证据
- ROI｜判断｜数据依据
- 消耗/转化成本｜判断｜数据依据
- 数据缺口或补充证据｜判断｜数据依据

## 风险判断
说明确定异常、正常延迟、数据不足，以及操作日志/广告备注/自动变更日志是否能解释变化。必须区分今日可能结算事件、后续上传设备确认、厂商 sent 实发导致的消耗/成本变化。引用日志时必须说明日志对应的计划快照和日期口径，如计划名、项目编码、回传编码、人群包、预算或时段。`PLAN_BASE_ONLY` 只能说明该日期缺计划指标证据，不能按 0 消耗判断。当天 ROI 为空时必须说明当天通常无 ROI。

## 优化动作
- 策略类别｜执行方式｜原因｜观察指标
- 策略类别｜执行方式｜原因｜观察指标
- 策略类别｜执行方式｜原因｜观察指标
```

ROI<1 默认简析：

```markdown
# 广告计划诊断

## 结论
建议：降本观察 / 暂不放量 / 继续观察。
最大问题：ROI 低于 1，当前只做轻量判断。

## 关键证据
- ROI｜低于盈亏线｜...
- 消耗/转化成本｜说明消耗规模或成本缺口｜...

## 优化动作
- 策略类别｜保守处理方式｜原因｜观察 ROI、消耗和转化成本
```

除非用户明确要求原因、优化、暂停判断、复盘、素材、回传、扣量或时段分析，否则 ROI<1 不展开完整归因链路。

## 横向对比

```markdown
# 多计划对比诊断

## 比较口径
说明同 productCode / returnDataCode / 负责人 / 人群包 / 日期；口径不一致时先分组，不直接排名。

## 结论
指出最该放量、稳投、降本或暂停观察的计划。

## 计划排序
| 建议 | planId | planName | 核心依据 | 风险 |

## 处理动作
- 计划｜策略类别｜执行方式｜原因｜观察指标
```

## 动作复盘

```markdown
# 动作复盘诊断

## 复盘口径
计划、queryDate、窗口天数、复盘的操作/变更类型。

## 复盘结论
有效 / 疑似无效 / 继续观察。说明证据强度和最大变化。

## 前后变化
- ROI/成本｜调整前｜调整后｜判断
- 回传/设备/留存｜调整前｜调整后｜判断
- 时段/素材/人群包｜调整前｜调整后｜判断

## 下一步动作
- 策略类别｜执行方式｜原因｜观察指标｜复核日期
```

## 巡检日报

```markdown
# 投放巡检日报

## 巡检口径
负责人 / 项目 / 回传编码 / 人群包，查询日期和窗口天数。

## 待放量
| planId | 计划 | 核心证据 | 建议动作 | 观察指标 |

## 待降本
| planId | 计划 | 核心风险 | 建议动作 | 观察指标 |

## 待暂停观察
| planId | 计划 | 暂停原因 | 恢复条件 | 观察指标 |

## 数据缺口
| planId | 计划 | 缺口维度 | 影响 | 下一步 |
```

## 措辞约束

- 直接写“建议降本”“建议稳投观察”“建议暂停放量”，不要写含糊的“可以关注一下”。
- 不要输出接口字段解释。
- 不要把次留、留存率、回传率写成 ROI。
- 不要把 `activationCount`、`returnCount`、`activeCount`、`activeDeviceCount`、`sent*` 或扣量比例写成 ROI。
- 不要把当天 ROI 为空写成异常；必须结合上传延迟说明。
- ROI<1 默认简短说明亏损状态和保守动作，不自动输出完整素材、时段、日志、raw 回传分析。
- 默认不要复述 MCP `summary.rows` 超过 20 行；ROI<1 每个计划最多写 1-2 条关键证据。
- 缺数据时写“暂无足够数据”，并说明缺哪个维度。
- 缺 `requestCounterExt` 或原始回传事件字段时，写“暂无扣量配置证据”或“暂无原始回传事件证据”，不要编造扣量比例。
- 工具失败、权限不足或超时时，必须说明诊断不完整，不要给强动作。
- 多候选未确认时，不输出深度诊断。
- `优化动作` 必须按“策略类别｜执行方式｜原因｜观察指标”输出；策略类别只能从提次留、降成本、提消耗、减少亏损中选择。
- 动作必须可执行，如“暂不放量，保持当前预算观察 1 天”“下调出价后看转化成本和 ROI”“限制高消耗低回传时段”；不要只写“优化投放”。
- 策略类别不是主结论，不能把“提次留/降成本/提消耗/减少亏损”替代“放量/稳投/降本/暂停观察/继续观察”。
- 扣量动作必须绑定 ROI 方向：ROI 高且稳定时可写“适当减少扣量/提高 sent 比例观察放量”；ROI 低或成本恶化时可写“增加扣量/降低 sent 比例控制成本”。
- 表达因果时要区分“导致”“可能相关”“暂无证据”；只有日志日期和指标变化匹配时才写“导致”。
- 动作复盘必须区分“有效”“疑似无效”“继续观察”，不能把建议动作写成已执行动作。
- 巡检日报只输出可处理清单；空数据、权限不足或工具失败进入“数据缺口”。
- 批量输出每个计划最多 1-2 条证据；不要复述原始 JSON rows。
