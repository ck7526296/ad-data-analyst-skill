# 项目规则

项目规则用于记录不同项目的结算、ROI、设备、回传、sent 实发和扣量口径。规则只解释诊断口径和动作阈值，不替代 MCP 数据、RuoYi 权限或计划范围。

## 读取优先级

1. 本地覆盖：`~/.codex/ad-data-analyst/rules/project-rules.md` 或 `project-rules.yaml`
2. Skill 仓库规则：本文件
3. 通用规则：`metrics.md`、`playbooks.md`

使用本地覆盖时，回答中说明“采用本地项目规则”。本地规则和仓库规则冲突时，本地规则优先；规则和 MCP 指标冲突时，MCP 指标是事实来源。

## 维护字段

每条项目规则建议包含：

- `productCode`：项目统计编码，必须可和 MCP 返回的计划身份匹配。
- 项目名称：便于人工识别。
- 生效日期：规则开始日期；有结束日期时同时写明。
- 结算口径：激活、回流、活跃、活跃设备、混合结算或其它明确口径。
- ROI 口径：只允许解释 `yesterdayQualityScore` 和 `cycleQualityScore` 的使用方式。
- 设备口径：最终设备、可能结算事件、项目统计兜底或上传确认方式。
- 回传口径：回传率、厂商回传、sent 实发、后续上传设备之间的关系。
- 扣量口径：`requestCounterExt`、sent 实发比例或其它限制条件；没有证据时写“暂无扣量配置证据”。
- 放量阈值：ROI、消耗、转化成本、设备质量、留存或连续天数要求。
- 降本阈值：触发降价、控量、换素材或观察的条件。
- 暂停观察条件：触发暂停或继续观察的证据要求。
- 特殊红线：该项目不能做出的推断。
- 维护人和更新时间：用于判断规则是否过期。

## 示例

```markdown
## 项目：示例项目
- productCode: demo_product
- 生效日期: 2026-06-01 起
- 结算口径: 激活 + 回流设备，T+1 上传确认
- ROI 口径: 只看 yesterdayQualityScore / cycleQualityScore
- 设备口径: 当天 activationCount / returnCount 只作可能结算线索，最终以后续上传设备为准
- 回传口径: sent 只代表厂商实发，不等于最终结算设备
- 扣量口径: 需要结合 requestCounterExt 和 sent 实发判断，不能用 deviceCount - sentTotalCount 固定推导
- 放量阈值: ROI >= 1 且消耗 >= 50，连续 2 天转化成本稳定
- 降本阈值: ROI < 1 或转化成本连续抬升
- 暂停观察: ROI 连续低于 1 且无上传延迟证据
- 特殊红线: 当天 ROI 为空不得直接判亏损
- 维护人: 用户自填
- 更新时间: 用户自填
```

## 使用规则

- 只有能通过计划身份确认 `productCode` 时，才把项目规则用于单计划结论。
- 只有用户要求项目横向对比，或工具返回同 `productCode` 范围，才把项目规则用于批量比较。
- 规则缺少生效日期或更新时间时，可以引用，但必须提示规则可能需要复核。
- 私有客户名、账号、token、后台权限、合同价格等敏感信息不要写入规则文件。
